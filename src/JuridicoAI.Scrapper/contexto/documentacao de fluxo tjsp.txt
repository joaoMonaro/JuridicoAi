DOCUMENTACAO DO FLUXO DE CONSULTA DE JURISPRUDENCIA TJSP - CJSG

1. Tela inicial da consulta

A tela de Consulta Completa da jurisprudencia do TJSP e carregada por:

GET https://esaj.tjsp.jus.br/cjsg/consultaCompleta.do

Essa pagina carrega o formulario principal e os scripts JS usados na consulta.

Formulario principal:

method="POST"
action="/cjsg/resultadoCompleta.do"

No HTML aparecem os campos:

O JS executa:

grecaptcha.execute(siteKey, { action: 'consulta' })

O token gerado e colocado no campo:

recaptcha_response_token

A pagina tambem chama o endpoint de controle de captcha:

POST https://esaj.tjsp.jus.br/cjsg/captchaControleAcesso.do

Payload:

uuidCaptcha=sajcaptcha_...&conversationId=

Resposta tipica:

{
  "uuidCaptcha": "sajcaptcha_..."
}

Esse uuidCaptcha atualizado deve ser usado no submit da pesquisa.

6. Download do inteiro teor

O JS do TJSP monta a URL assim:

var url = window.saj.env.root + "/getArquivo.do?cdAcordao=" + cdAcordao + "&cdForo=" + cdForo;

URL final:

GET https://esaj.tjsp.jus.br/cjsg/getArquivo.do?cdAcordao=20611872&cdForo=0

Esse endpoint abre o PDF/inteiro teor do acordao.

7. Paginacao

A primeira pagina vem no POST /resultadoCompleta.do.

As paginas seguintes sao carregadas por AJAX:

GET https://esaj.tjsp.jus.br/cjsg/trocaDePagina.do?tipoDeDecisao=A&pagina=2

Parametros:

- tipoDeDecisao=A
- pagina=2

Tipos de decisao observados:

- A = Acordaos
- H = Homologacoes de acordo
- D = Decisoes monocraticas

O JS responsavel esta em filtrosLaterais.js:

var trocarDePagina = function(valor){
  var tipoDeDecisao = valor.charAt(0);
  var pagina = valor.slice(1);
  var url = window.saj.env.root + "/trocaDePagina.do";
  var params = {tipoDeDecisao: tipoDeDecisao, pagina: pagina};

  $.ajax({
    url: url,
    data: params,
    type: 'GET',
    cache: true,
    success:function(html) {
      mostraResultados(html,tipoDeDecisao);
    }
  });
};

O retorno de trocaDePagina.do e HTML parcial.

O JS divide a resposta por:

#%#quebra_resposta#%#

Quando existem 3 partes:

resp[0] = HTML dos resultados
resp[1] = HTML de termos relacionados/adicionar pesquisa
resp[2] = HTML da paginacao

8. Filtros laterais

Depois da primeira busca, os filtros laterais usam AJAX.

Montar filtros:

POST /cjsg/montaFiltro.do

Refinar resultados:

POST /cjsg/montaResultados.do

Payload base:

tipoDecisao=A

Com filtros:

tipoDecisao=A
&classe=...
&relator=...
&comarca=...
&orgaoJulgador=...

O retorno tambem e HTML parcial separado por:

#%#quebra_resposta#%#

9. Fluxo resumido para implementar

1. Fazer GET /cjsg/consultaCompleta.do.
2. Guardar cookies da sessao.
3. Extrair uuidCaptcha inicial.
4. Gerar recaptcha_response_token via browser/ambiente capaz de executar reCAPTCHA.
5. Fazer POST /cjsg/captchaControleAcesso.do com uuidCaptcha.
6. Atualizar uuidCaptcha com a resposta.
7. Fazer POST /cjsg/resultadoCompleta.do com os campos da busca.
8. Parsear #divDadosResultado-A da primeira resposta.
9. Extrair os 20 resultados da pagina.
10. Para pagina 2 em diante, chamar GET /cjsg/trocaDePagina.do?tipoDeDecisao=A&pagina=N.
11. Parsear o HTML parcial retornado.
12. Para PDF/inteiro teor, chamar GET /cjsg/getArquivo.do?cdAcordao=X&cdForo=Y.

10. Pontos criticos

- Cookies precisam ser mantidos entre todas as chamadas.
- recaptcha_response_token expira.
- uuidCaptcha muda.
- O resultado depende da sessao.
- Reusar curl antigo tende a retornar so o formulario vazio.
- A primeira pagina vem no POST resultadoCompleta.do.
- As proximas paginas vem no GET trocaDePagina.do.
- O endpoint nao retorna JSON de jurisprudencia; retorna HTML.

12. Conclusao

A jurisprudencia nao vem de uma API JSON.

Ela vem como HTML renderizado pelo servidor.

A primeira leva de resultados esta na resposta de:

POST /cjsg/resultadoCompleta.do

As paginas seguintes vem de:

GET /cjsg/trocaDePagina.do

O PDF/inteiro teor vem de:

GET /cjsg/getArquivo.do?cdAcordao={id}&cdForo={foro}
